# `sc review`（実レンダー A/B 試聴画面）設計

日付: 2026-08-01

## 背景 / 課題

stefnceorf は削除候補（フィラー・未転写発話候補・無音トリム）を
その場で再生確認できない。候補が多いと .sc.txt 編集と DAW の往復がつらい。

## 決定事項

1. **`sc review episode.sc.txt`** で必要時に生成（常時生成しない。手動編集後の状態を反映できる）
2. **実 render() 出力で A/B 試聴**。擬似再生（`timeupdate` での区間スキップ）は
   発火間隔が粗く（約 250ms）100–150ms のカットを通過しうる上、
   クロスフェード・エッジスナップを再現しないため不採用
3. **読み取り専用＋判断支援に徹する**。保存機能（.sc.txt への書き戻し）は持たない
   - 保存はローカルサーバーと状態管理を要求し肥大化の入口になる。「.sc.txt が唯一の真実」を維持
   - 削除切替 UI も当面持たない。確定は .sc.txt を手で編集 → `sc review` 再実行
4. スコープ外: 波形表示、ズーム、単語単位編集、ドラッグ編集、動画・字幕プレビュー

## 構成

**単一 HTML＋隣接音声ファイル**(自己完結 HTML ではない。音声は外部参照):

- `episode.review.wav`: 現在の .sc.txt から実 render したレビュー音声（専用名。既存出力を上書きしない）
- `episode.review.html`: 原音 wav とレビュー音声の 2 つの `<audio>` を参照
- 生成後にブラウザで自動オープン（`--no-open` で抑止）

## 処理フロー

1. `build_edit_plan()` を**1回だけ**実行し、同じ `EditPlan` からレビュー WAV と写像表の両方を作る
   - 現行 `render()` は内部で再計画するため、音声書き出し部分を `render_plan(plan, output)` 等へ分離
2. 入力は **JSON と TXT の両方**:
   - `.sc.json`: 全行・原音区間・種別（`reason: "uts"` 含む）の正
   - `.sc.txt`: 現在の採否・順序
3. 元時刻→編集後時刻の**写像表**を review.py 内で構築（`EditPlan` は変更しない）:
   - JSON 各 segment の原音区間 × 出力順の各 `output_interval` の共通部分を計算
   - クロスフェード込みの出力開始サンプルを累積し
     `{segment_id, source_start/end, output_start/end}` を生成
   - 削除 segment は TXT 上の前後 kept segment から結合境界を決定
   - サンプル単位で計算し、実レンダー（`crossfade_concat`）と同じ丸めを使う

## HTML 機能

- タイムスタンプ付きトランスクリプト。削除済み行も取消線で表示
- ハイライト: フィラー（JSON の `suggest: True` 単語を個別クリック対象に）・
  `reason: "uts"` 行・無音トリム
- 行/単語クリックで該当位置±数秒を再生。原音/編集後トグル
  （削除箇所は編集後側では結合境界を再生）
- 注記を表示: この A/B は `sc render` 結果に対して正確。Logic 用 FCPXML は削除を
  タイムライン空白として残すため、Logic 上の再生とは異なる
- 埋め込み JSON は `</script>` 分割・HTML エスケープ対策

## テスト

- HTML 生成（区間データ埋め込み、エスケープ、wav 相対パス解決、削除済み行の表示）
- 写像表: 共通部分計算、クロスフェード補正込み累積、削除 segment→結合境界、
  並べ替え時の対応、実レンダー出力長との一致（サンプル単位）
- `render_plan` 分離後の既存 `sc render` 回帰
- 小型 wav での統合テスト。review.wav が既存出力を上書きしないこと

## 不採用にした代替案

- **擬似編集再生（timeupdate スキップ）**: 決定事項 2 の理由で撤回
- **ローカルサーバー型（トグル＋保存付き）**: 肥大化リスクで見送り
- **`sc play` CLI のみ**: 候補が多いと往復がつらく根本解決にならない
- **vidtighten 級の波形編集 GUI**: 別製品化するため不採用
- **常時 HTML 生成**: 手動編集後の状態を反映できず成果物も増えるため、必要時生成に変更
